Reports and downloads

Colours show report types. The line shows npm requests. The default view gives each series a before-merge mean of 100.

Read this chart

In the growth view, both series use the left axis. Each has its own before-merge mean of 100. A taller report stack means greater relative growth at that date.

In the count view, reports use the left axis. npm requests use the right axis. In the rate view, reports are divided by npm requests for the same dates.

A seven-day point uses the previous seven complete calendar days. Rates divide the sum of reports by the sum of requests. They do not average daily ratios.

Missing downloads and incomplete days appear as gaps in rates and indices. Raw daily counts can include the incomplete last day. The summary uses the full comparison period. Zoom and legend changes do not change that summary.

The version filter changes reports only. npm requests still include all versions. We cannot calculate a failure rate for each version from these inputs.

Each report appears once in a stack. One title match keeps its type. Several matches use the several-types group. No match uses the no-match group.

Crashes and memory leaks

Both report rates decreased after the merge. The leak group requires evidence of memory not released after use. High memory use alone is a separate group.

Check the periods and memory-leak evidence

The comparison uses 181 days before the merge and 167 days after it. The periods are 14 November–13 May and 15 May–28 October. They contain 23,077,916 and 70,541,010 npm requests.

We exclude the merge day and incomplete issue-window days from the table. We also exclude unpublished download dates. One report can match both crash and leak rules. Do not add the rows.

The main check uses titles. The extra check adds up to 2,500 body characters on each side. It removes fenced code. Body text can mention problems that did not occur. The old and new excerpt formats also differ.

The leak group includes allocated memory that remains held, including leaks found at process exit. Generic OOM, high RSS and memory corruption are separate. Disk files, file descriptors and a test-cap failure are excluded.

The leak sample is small. Some reports can describe the same defect. The crash rule also has known false matches. Before-merge text and labels come from August. After-merge observations come from October.

After-merge reports can concern old Zig builds. npm includes repeat requests and automated jobs. It omits other channels. These rates do not prove a Rust effect or measure risk per user.
