# Crashes and memory reports in three release periods

The comparison uses saved reports and npm daily data through **28 October 2026**. Report date and runtime implementation are separate. Stable stayed on Zig during the Rust canary period. Later reports can still concern Zig versions.

## Complete-day periods

| Period | Dates | Days | Reports | npm requests | Reports per million requests |
| --- | --- | ---: | ---: | ---: | ---: |
| Before merge | 2025-11-14–2026-05-13 | 181 | 1,772 | 23,077,916 | 76.78 |
| Canary period | 2026-05-15–2026-08-19 | 97 | 985 | 34,698,894 | 28.39 |
| After Rust stable | 2026-08-21–2026-10-28 | 69 | 1,338 | 35,306,720 | 37.90 |

Both event days, **14 May and 20 August**, are excluded. The events occurred partway through each day. Partial issue-window endpoints and unpublished npm dates are also excluded. All counts in rate tables use the same matched days.

## Title-only rules

Each cell shows count / reports per million all-version npm requests.

| Report type | Before merge: count / rate | Canary period: count / rate | After stable: count / rate | Stable vs canary rate |
| --- | ---: | ---: | ---: | ---: |
| All possible bug reports | 1,772 / 76.783 | 985 / 28.387 | 1,338 / 37.896 | +33.5% |
| Crash reports | 404 / 17.506 | 118 / 3.401 | 71 / 2.011 | -40.9% |
| Memory leak reports | 15 / 0.650 | 7 / 0.202 | 5 / 0.142 | -29.8% |
| Memory keyword reports | 27 / 1.170 | 10 / 0.288 | 14 / 0.397 | +37.6% |

The general report rate and broad memory rate are higher after stable than during the canary period. Crash and explicit leak rates are lower. A substantial crash-rate decline occurred before Rust stable. No causal Rust effect is estimated.

Leak counts are small: **15 / 7 / 5**. The rule requires explicit memory or allocation retention text. It includes GC roots, retained native memory, and leaks found at shutdown. It excludes generic high memory usage, OOM alone, growing files, file-descriptor leaks, and a test-cap flake. [Per-report evidence](data/safety-audit.jsonl) records flags and titles. The HTML links **27 leak-title matches** from these complete-day periods. A leak report on the stable-release day is excluded from period rates, but remains in the full data.

The crash rule can match unrelated crash-report metadata. Reports can duplicate one defect or concern old builds, embedded runtimes, or JavaScriptCore. A match does not verify an incident or cause.

## Rolling rates and reference

For a window W:

`Q(W) = (reports(W) / npm requests(W)) / (before-merge reports / before-merge npm requests)`

Q also equals the report growth index divided by the npm growth index. Q = 1 is the before-merge reference. Below 1 means fewer reports per request than that reference. A rising curve means the relative rate is increasing.

The canary-period all-report rate is **0.370×** the reference. The after-stable rate is **0.494×**, which is **33.5% higher than the canary-period rate**. These are calendar summaries across all versions, not Zig/Rust exposure estimates.

Windows divide total reports by total requests. Missing/zero denominators and partial report days appear as gaps. Rolling windows can cross event dates. Separate summaries exclude both event days. Period rates are not averages of the rolling curve.

## Version families and limits

The [version map](README.md) groups reports using stated version lines. Missing, multiple, conflicting-date, and uncertain development versions stay unclear. Calendar periods do not assign language families.

npm counts repeat requests and automated builds. It excludes other installation methods. There are no historical daily npm denominators by version or language family. No chart measures defects per active user or per Rust installation. See [source limits](POPULARITY-SOURCES.md).

## Build and check

`python3 part3/build.py` builds the data and charts. `pnpm run verify` checks phase boundaries, shared days, denominators, title/body counts, leak-rule cases, family totals, and equivalent Q formulas. [safety.py](safety.py) defines the leak rule. [data/safety.json](data/safety.json) stores the summaries.
