# Crash and memory reports per million npm requests

This comparison uses saved reports and npm data through **28 October 2026**. It includes **181 days before** the merge (14 November 2025–13 May 2026) and **167 days after** it (15 May–28 October 2026). It excludes the merge day, partial report days, and unpublished npm dates. npm totals are **23,077,916 before** and **70,541,010 after**.

| Title match | Before: reports | Before: per million requests | After: reports | After: per million requests | Rate change |
| --- | ---: | ---: | ---: | ---: | ---: |
| Crash or fatal signal | 404 | 17.506 | 190 | 2.693 | −84.6% |
| Memory leak or retained memory | 15 | 0.650 | 13 | 0.184 | −71.6% |
| All memory problems, including OOM and corruption | 27 | 1.170 | 25 | 0.354 | −69.7% |


The report rates fell. This does not prove that Rust reduced confirmed defects or failures per user. The leak count changes only from **15 to 13**. Most of its rate decrease comes from the larger npm total. Several reports can describe one defect. Reports can also concern old Zig builds, embedded Bun runtimes, or JavaScriptCore.

The leak rule requires explicit evidence of a memory leak or retained allocations in the title. It includes GC roots, retained native memory, and leaks found at shutdown. It excludes general high memory use, out-of-memory errors, growing files, file-descriptor leaks, and a test-cap flake. A separate rule counts all memory problems. The crash rule can match context such as crash-report metadata. [Per-report evidence](data/safety-audit.jsonl) keeps the flags and original titles. The HTML links all 28 primary leak matches in these comparison dates.

## Body text check

This check adds up to 2,500 body characters to the title.

| Title + up to 2,500 body characters | Before: reports / rate | After: reports / rate | Change |
| --- | ---: | ---: | ---: |
| Crash or fatal signal | 571 / 24.742 | 306 / 4.338 | −82.5% |
| Memory leak or retained memory | 29 / 1.257 | 17 / 0.241 | −80.8% |
| All memory problems | 70 / 3.033 | 63 / 0.893 | −70.6% |


The direction stays the same. This is an additional check, not proof that matches are correct. Body mentions can be unrelated or negated. Older excerpts use plain text; newer excerpts retain Markdown. Removing fenced code does not remove every formatting difference. Before-merge observations were collected in August; after-merge observations were collected in October. Neither method establishes the cause, severity, or number of unique defects.

## Relative report rate

For a time window W, the separate chart uses:

`Q(W) = (reports(W) / requests(W)) / (before-merge reports / before-merge requests)`

This also equals the report growth index divided by the npm growth index. Each index uses its own before-merge daily mean. **Q = 1** is the reference. Below 1 means fewer reports per npm request than before the merge. A rising line means the rate is increasing over that interval, even if it remains below 1. The formula does not divide percentage changes.

For all reports, the after-period rate divided by the before-period rate is **0.435× (−56.5%)**. Choose all reports, crashes, leaks, or all memory problems. Choose title-only or body text checks and 1-, 7-, or 28-day windows. Each window divides total reports by total requests. Missing or zero request counts, partial report days, and missing reference rates appear as gaps. Windows across the merge include both periods. The period summary compares the two periods separately. It does not average the rolling line.

npm requests include automated builds and repeat downloads. They exclude other installation methods and do not count unique or active users. Reports and requests therefore cover different groups. Q does not measure defects per user. See [source limits](POPULARITY-SOURCES.md).

## Build and check

`python3 part3/build.py` builds the safety data and both charts. `pnpm run verify` checks dates, request totals, report counts, rate changes, leak-rule cases, and the two equivalent Q formulas. [safety.py](safety.py) defines the leak rule. [data/safety.json](data/safety.json) stores daily counts and summaries.
